## 2. Technical Concepts & Observations

### 2.1 Resource State
- **Scheduling:** Scheduling adds CPU and memory to the used resource fields.
- **Release:** Releasing removes CPU and memory from the used resource fields.
- **Validation:** The program must check the full operation before it changes state.
- **Invariant:** Used CPU and used memory must not become negative or exceed node capacity.
- **Return Values:** A method that returns `bool` reports success or failure. The caller must use the result when the result matters.

### 2.2 Node Lifecycle
- **Healthy:** A healthy node can work normally.
- **Unhealthy:** An unhealthy node cannot receive new workloads.
- **Draining:** A draining node cannot receive new workloads, but existing resources remain in use.
- **Recovery:** Recovery marks the node healthy and removes the draining state. It does not erase resource use.
- **State Separation:** Unhealthy and draining are different states. One node can have either state or both states.

### 2.3 Selecting Nodes
- **Eligible Node:** A node is eligible when it is healthy and not draining.
- **Most Available:** `FindMostAvailableNode` selects the eligible node with the most available CPU.
- **Least Loaded:** `FindLeastLoadedNode` calculates CPU and memory use as ratios and uses the higher ratio as the node load.
- **Safe Result:** Both selection functions return `nil` when no eligible node exists.
- **Pointer Result:** The selection functions return a pointer to an element in the original slice, not to a copy.

### 2.4 Review and Verification
- **Build Checks:** `gofmt`, `go test`, and `go vet` pass.
- **Runtime Checks:** The program schedules five workloads, rejects an impossible workload, rejects scheduling on unhealthy and draining nodes, releases resources, recovers a node, and prints a report.
- **Manual Review:** A successful build does not prove that state changes are correct. The output and each state transition must also be checked.

## 3. Root Cause Analysis & Pitfalls
- **Ignored Boolean Result:** Calling a method that returns `bool` as a statement discards the success or failure result.
- **Wrong State Change:** Draining a node must not change its used resources or mark it unhealthy.
- **Lost Resource State:** Recovering a node must not reset used resources to zero.
- **Selection Logic:** A minimum search must start with the first valid candidate. Starting the minimum at zero selects the wrong result for non-negative values.
- **Boolean Logic:** Eligibility needs all required conditions. Use logical AND for healthy, not draining, and valid capacity checks.
- **Division by Zero:** Utilization must not divide by zero. Nodes with zero CPU or memory capacity must be excluded or handled separately.
- **Report Meaning:** A report must define whether available capacity means all available capacity or only schedulable capacity.

## 4. Architectural Takeaways & Next Milestones
- **State Transitions:** Platform code is mainly state management. Each operation must preserve the system invariants.
- **Small Methods:** Methods such as `Drain`, `Undrain`, `MarkHealthy`, and `Release` keep changes close to the data they modify.
- **Cluster Coordination:** Cluster methods choose nodes and call node methods. The cluster should not duplicate node state rules.
- **Review Cycle:** Review, fix, run, and review again is a valid engineering workflow.
- **Next Milestone:** Continue with Go interfaces after the project is complete. Later, add workload tracking, tests, persistence, and concurrency one step at a time.

## 5. Reference Implementation
```go
func FindLeastLoadedNode(nodes []Node) *Node {
	var node int
	var util float64
	found := false

	for i := range nodes {
		if nodes[i].Healthy && !nodes[i].Draining && nodes[i].CPU > 0 && nodes[i].Memory > 0 {
			cpu := float64(nodes[i].UsedCPU) / float64(nodes[i].CPU)
			memory := float64(nodes[i].UsedMemory) / float64(nodes[i].Memory)
			nodeUtil := max(cpu, memory)

			if !found || nodeUtil < util {
				node = i
				util = nodeUtil
				found = true
			}
		}
	}

	if !found {
		return nil
	}

	return &nodes[node]
}
```
