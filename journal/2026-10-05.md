# Technical Log: 2026-10-05

## 1. Objective Analysis
Studied Go methods through the Methods section of *A Tour of Go*, focusing on receiver syntax, value receivers, pointer receivers, and the difference between methods and ordinary functions. Implemented examples in a dedicated `dmethods` package and designed a platform-engineering exercise around node health and resource scheduling.

## 2. Technical Concepts & Observations

### 2.1 Methods and Receivers
- **Method Definition:** A method is a function with a receiver declared between the `func` keyword and the method name.
- **Receiver Ownership:** A method is associated with its receiver type, allowing behavior to be expressed directly on values such as `Vertex`, `MyFloat`, or a future infrastructure type such as `Node`.
- **Value Receiver:** A receiver such as `(v Vertex)` operates on a copy of the value and is appropriate for read-only behavior such as calculating a vertex's absolute length.
- **Pointer Receiver:** A receiver such as `(v *Vertex)` operates through a pointer to the original value and can mutate its fields.

### 2.2 Method and Function Invocation
- **Method Form:** `v.Abs()` communicates that the operation belongs to the `Vertex` value.
- **Function Form:** An equivalent operation could be written as `Abs(v)`, where the receiver becomes an ordinary function argument.
- **Pointer Mutation:** `v.Scale(10)` can call a pointer-receiver method because Go automatically takes the address of an addressable variable, effectively treating the call as `(&v).Scale(10)`.
- **Receiver Consistency:** Methods that change state should generally use pointer receivers, while read-only methods can use value receivers.

### 2.3 Named Types and Domain Behavior
- **Named Numeric Type:** `type MyFloat float64` creates a distinct named type that can have its own methods.
- **Local Receiver Requirement:** Methods can be declared only for a receiver type defined in the same package; methods cannot be added directly to built-in or imported types.
- **Domain Modeling:** The method pattern provides a natural foundation for platform objects such as nodes, workloads, files, connections, and resource pools.

## 3. Root Cause Analysis & Pitfalls
- **Accidental Copy Mutation:** Using a value receiver for a method intended to update state changes only a copy, leaving the original value unchanged.
- **Pointer versus Value Function Arguments:** A function with a pointer argument requires an explicit pointer, such as `ScaleFunc(&v, 10)`, while a method call may receive automatic address-taking for an addressable value.
- **Receiver Variable Confusion:** The receiver variable is local to the method, but it represents the value or pointer supplied by the caller. The method name is attached to the type, not to one single variable instance.
- **Executable Package Requirement:** A directory using `package dmethods` is a library package and cannot be run directly with `go run .`; an executable requires `package main` and a `main` function.

## 4. Architectural Takeaways & Next Milestones
- **Behavior Near State:** Methods are appropriate when behavior operates on one particular value, while ordinary functions are better for general operations or comparisons across multiple values.
- **State-Safe Mutation:** Pointer receivers are the mechanism for changing node state such as health, draining status, and allocated resources without copying the node.
- **Platform Engineering Exercise:** The next project is a mini control plane that models worker nodes, resource capacity, scheduling, draining, recovery, and cluster reporting.
- **Future Integration:** Continue through Go's interfaces section after completing the exercise, then use interfaces to model interchangeable platform components such as schedulers, health checks, and resource providers.

## 5. Reference Implementation
```go
package dmethods

import (
	"fmt"
	"math"
)

type Vertex struct {
	X, Y float64
}

func (v Vertex) Abs() float64 {
	return math.Sqrt(v.X*v.X + v.Y*v.Y)
}

func (v *Vertex) Scale(f float64) {
	v.X = v.X * f
	v.Y = v.Y * f
}

func Methods() {
	v := Vertex{3, 4}
	v.Scale(10)
	fmt.Println(v.Abs())
}
```
